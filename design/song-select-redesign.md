# 選曲画面の描画刷新

基点: PR #17がマージされた`feature/integrate-design-unit-test`の`c41b19b`。
実装ブランチ: `feature/song-select-redesign`。

## 画面

- 1280×720のゲーム描画領域。既存の和柄素材に薄い色を重ね、赤・生成り・墨色で統一。
- 左側に選択曲の大きな曲名、太鼓のモチーフ、試聴表示、5段階の難易度カード、決定案内。
- 右側に最大7曲の一覧。選択行を強調し、選択に追従して表示範囲とスクロールバーを更新。
- 難易度カードにレベルを表示。譜面なしは灰色のカードで明記し、選択中は枠と矢印で示す。
- ヘッダーに「選曲→難易度」の段階と曲番号、下部に現在の操作案内。
- 曲名はUTF-8を壊さず計測。詳細は2行、一覧は1行に収め、必要なら省略記号を付ける。
- 曲がない場合・読み込みエラー・デモからのフェード復帰を専用表示で扱う。

## 接続と所有権

`SongSelectView`は描画、軽いアニメーション、フォント/背景の寿命だけを持つ。
`SongSelect`の選曲、難易度移動、試聴停止/開始、自動デモ待機、共有カーソル、譜面ロード、シーン遷移を維持。
新しい音源の所有者や毎フレームのフォント/画像ロードは作らない。
背景/フォント読み込み失敗時は単色背景/既定フォントへ戻す。Finalizeとデストラクタの解放は冪等。
既存の試聴待機時間中は「試聴待機中」と表示する。

操作は従来どおりD/Kで移動、F/Jで決定。難易度の左端でDを押すと曲選択に戻る。マウス操作は追加していない。

## 検証

- GitHub Actionsで実際のSongSelect/Input/SongData/Viewをコンパイルし、選曲・デモ復帰・通常開始をWindows/MSVC ASanとLinux ASan/UBSanで検査。
- デモ制御・ChartPlayer・リザルトの既存テストも実行。
- 描画専用検査では通常、難易度選択、譜面なし、長い日本語曲名、エラー、フェード、1曲、空、素材欠損の9状態を記録。
- 同じ本番Viewから描画命令をJSONLに記録し、`tests/render_song_select_captures.py`で確認用PNGを生成。文字計測は近似であり、DxLib実機スクリーンショットではない。
- フォントの二重解放/リーク、背景の解放、ブレンド状態の復元も検査。

## 実機での確認

LIFEBOOK上では引き継ぎに従いゲームのビルド/起動を行わない。作業機で更新を取得し、プロジェクトを再読み込みしてリビルドする。
日本語フォントの実際の余白、ウィンドウ/全画面表示、キー連打、難易度の左右端、30秒後のデモ、戻りフェードと音声を確認する。
メタデータ解析、入力、音源の仕様変更はこのPRの範囲に含めない。
